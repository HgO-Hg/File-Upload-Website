# 文件中转站（File Upload Website）

一个**无验证、无登录**的临时文件中转网站：把文件拖进网页 → 生成一条下载直链 → 把链接发到另一台设备打开即可取件。

前端是一个**纯静态**的 `index.html`，可部署在任意静态托管上；真正接收和存储文件的是后端 Serverless 函数 + S3 兼容对象存储。

---

## 功能特性

| 功能 | 说明 |
| --- | --- |
| 拖拽 / 点击 / 粘贴上传 | 支持拖入、点击选择、多选，以及直接 `Ctrl+V` 粘贴截图 |
| 文件队列 | 最多 200 个文件排队，逐条显示进度、成功/失败状态 |
| 大文件分片上传 | 超过阈值的文件自动切分为多片上传后合并 |
| 断点续传 | 上传会话缓存在 `localStorage`，刷新或换浏览器后可从已传分片继续 |
| 取消上传 | 可中断正在进行的请求（基于 XHR abort） |
| 保存时长 | 1 小时 / 6 小时 / 1 天 / 7 天 / 30 天 / 永久 |
| 取件码（分区） | 给文件打一个分区标签，同码可见；**不是密码，不提供加密保护** |
| 取件 / 下载 | 按取件码刷新列表，或直接粘贴下载直链打开 |
| 自动复制链接 | 上传完成自动复制直链，并弹出提示 |

界面为深色渐变风格（`#1a1a2e` → `#0a1929`，主色 `#0267f4`，强调色 `#ff69b4`），带鼠标跟随粒子特效、加载动画与响应式布局（适配 768px / 480px 断点）。

## 重要限制与注意事项

**分片大小会被自动裁剪。** 下拉选项不是硬编码：在 Netlify（约 4.5MB）、Vercel（4.5MB）这类有请求体上限的平台上，前端只列出放得下的档位（受限时按 3MB 保守估算），避免“显示 16MB 实际被夹到 3MB”的错觉。用户手动选过之后不会被覆盖。

**受限后端传不了大文件。** 对象存储要求**非末尾分片不小于 5MiB**，而受限平台的单请求上限只有 4~6MB，两者冲突：当后端单请求上限低于 5MiB 时，分片方式凑不出合法分片，此时**可传的最大文件就等于该上限**。前端会直接明确拒绝并说明原因，而不是切出一堆碎片到最后合并才失败。要传大文件请改用 Cloudflare Worker 后端。

**分片过多会在合并阶段失败。** 合并请求每个分片要消耗 2 次 R2 操作，免费额度为单次调用 1000。前端把安全片数控制在 400 片以内，超出会提示你把分片调大。

**取件码不是密码。** 它只是分区标签，知道取件码的人都能看到该分区文件，不能作为加密手段。

**安全提醒。** “无验证上传”意味着任何拿到网址的人都能上传和下载。建议在服务端设置体积上限与保存时长并定期清理；涉密或私人文件不要走这条链路。

**上传中别刷新。** 队列与进度保存在内存中，刷新即丢失；页面会在离开时弹出确认提示。单次请求超时保护为 20 分钟。
